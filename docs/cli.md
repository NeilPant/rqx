## `rqx check`

Analyze changed files against a base revision and fail if the gate is not met

| Flag | What it does |
| --- | --- |
| `--base` | Revision to compare against |
| `--staged` | Review what `git commit` would record: the staged contents, read from the index. Unstaged edits do not affect the verdict. The rest of the project is read from the working tree |
| `--fix` | Apply the mechanical fixes to the files the branch changed before gating, so a branch whose only failures are mechanical passes |
| `--write` | With --fix, write the fixes. Without it no file changes |
| `--severity` | Show only findings at or above this severity |
| `--rule` | Show only this rule; repeatable |
| `--category` | Show only this smell family; repeatable |
| `--path` | Show only findings in files matching this glob; repeatable |
| `--not-rule` | Hide this rule; repeatable |
| `--not-category` | Hide this smell family; repeatable |
| `--not-path` | Hide findings in files matching this glob; repeatable |
| `--confidence` | Show only verified findings, or only heuristic ones |
| `--fixable` | Show only findings `rqx fix` can act on |
| `--search` | Show only findings whose rule, file or evidence contains this text |
| `--since` | Show only findings in files this revision changed |
| `--changed` | Show only findings in files not yet committed |
| `--files-from` | Show only findings in the files this list names, one path per line, or separated by NUL when the input holds one (`git diff -z --name-only`); `-` reads standard input. Paths are relative to the scanned directory, or absolute. The whole project is still analysed, so cross-file findings remain correct. On `check` the list replaces the git diff as the files under review |
| `--show-passed` | Also list files with no findings |
| `--quiet` | Print the summary without the findings |
| `--timings` | Print how long each stage of the scan took, and what it did |
| `--stats` | Counts only: the number of findings per rule and per family |
| `--group-by` | What findings are grouped by |
| `--sort` | Sort order inside each group |
| `--top` | List only this many groups; the rest are counted |
| `--show-suppressed` | Also list the findings a source comment waives |
| `--context` | Lines of code shown on each side of a finding. Defaults to 2 under `--detail full` and 0 otherwise |
| `--detail` | How much of each finding to print |
| `--reporter` | Where a report goes: `<name>` for stdout, `<name>=<path>` for a file; repeatable. `html` is deprecated and will be removed in 0.6.0 |
| `--fail-on` | Lowest severity that fails the run |
| `--allow-findings` | Findings allowed before the run fails |
| `--min-health` | Health score below which the run fails; 0 disables |
| `--min-grade` | Lowest grade any single file may carry |
| `--fail-on-incomplete` | Fail when a design pattern is half applied |
| `--coverage` | A coverage file that can contradict a dead-code finding. lcov, a Go cover profile and coverage.py JSON are detected by content |
| `--profile` | A CPU profile that can contradict a performance finding. A V8 .cpuprofile, a Go pprof, speedscope JSON, JFR text and collapsed stacks are detected by content |
| `--sarif-in` | A SARIF 2.1.0 file another tool wrote (ruff, ESLint, Semgrep), read as findings in the `external` family. They count for the gate and the reports and not for the health score |
| `--max-findings` | Maximum number of findings listed; 0 lists every finding. Does not affect the health score |
| `--record` | Append a snapshot of this scan's health to a trend file. Without a path it writes to `.rqx/trend.ndjson` |
| `--trend` | Draw the snapshots in this file as a chart in the HTML report. A file that does not exist yet draws nothing |
| `--regressions` | List the functions whose time order grew against the base revision, even when `gate.complexity_regression` is `off`. They are reported and do not change the exit code; the setting does that |
| `--level` | relaxed, standard, strict or pristine |
| `--threads` | Worker threads. Defaults to the machine's parallelism |
| `--config` | Read settings from this file, layered over any `rqx.yaml` found |
| `--no-tui` | Do not open the interactive interface; bare `rqx` prints the report instead |
| `--color` | When to colour output; `auto` follows NO_COLOR and whether stdout is a terminal |
| `--motion` | Animation in the interactive interface |
| `--no-progress` | Do not draw the progress bar on stderr; `--quiet` implies it |
| `--progress` | How a scan reports progress on stderr; `plain` prints a line every two seconds for a job log |
